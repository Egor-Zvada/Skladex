# Доменный вход

Skladex поддерживает Active Directory по LDAPS либо обязательному StartTLS. Bind выполняется после проверки сертификата контроллера и доверенного CA. Запись в каталог, изменение пароля или групп не реализованы.

В production на 17.10.2026 разрешены только группы Admin-NC и Администраторы домена. Обе временно получают роль администратора по указанию владельца. Группы Nextcloud, дающие всем сотрудникам доступ к облаку, сюда не переносятся. Когда появятся отдельные группы Skladex, заменить сопоставление на роли viewer/operator/admin. Учитывается вложенное членство и основная группа.

Идентичность привязана к двоичному objectGUID AD. Доменные пользователи создаются при первом успешном входе; существующие локальные записи с ними не объединяются по почте или логину. Пароль домена не сохраняется. Локального пароля у доменной записи нет. Локальный admin остаётся доступным при недоступности AD.

На защищённом запросе доменное разрешение старше 60 секунд проверяется заново. Удаление из разрешённых групп или отключение в AD блокирует запись и отзывает сеансы/токены до отказа в доступе. Изменение роли также отзывает старые сеансы и токены. При сбое каталога просроченное разрешение не продлевается: возвращается временная ошибка. Уже проверенное разрешение может действовать до 60 секунд. Ручная блокировка в Skladex не снимается успешным доменным входом.

Имя, почта, логин и роль доменной записи управляются AD. В Skladex можно заблокировать доступ; нельзя подменить доменную идентичность или назначить локальный пароль. Последний активный локальный администратор защищён от блокировки и понижения.

## Защищённая конфигурация

LDAP_ENABLED=true включает доменный вход. LDAP_CONFIG_FILE указывает на /etc/skladex/ldap.json, читаемый при обращении к каталогу, вне Laravel config cache. Файл root:skladex, права 0640, каталог закрыт от посторонних. JSON содержит enabled, hosts (DNS-имена без URI), port, mode (ldaps/starttls), base_dn, bind_dn, bind_password, ca_file, netbios и groups: DN группы, role, числовой primary_group_id. Пароли и действительные DN в репозиторий не включаются.

CA: /etc/skladex/ldap-ca.pem. Требуется php8.4-ldap. После изменения окружения пересобрать config cache и перечитать PHP-FPM. JSON и CA читаются из отдельных файлов. Настройки входят в закрытый архив /etc/skladex, создаваемый deploy/backup.sh; его нельзя публиковать с исходниками или дампом данных.

Проверка каждого контроллера без изменения каталога и вывода реквизитов:

    cd /srv/skladex/app
    runuser -u skladex -- php artisan skladex:directory-check

Команда проверяет TLS, служебный bind и чтение базового объекта. Она не подтверждает вход конкретного сотрудника: его пароль проверяется только в обычной форме входа. Форматы: доменный логин, VVE\логин или доменная почта.

Источники: [PHP LDAP TLS options](https://www.php.net/manual/en/function.ldap-set-option.php), [Microsoft AD transitive matching rule](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/4e638665-f466-4597-93c4-12f2ebfabab5).

Настройки Nextcloud использованы только для чтения. Код, БД и конфигурация Nextcloud в рамках интеграции не изменяются.
