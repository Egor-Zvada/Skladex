# Документы по оборудованию

Раздел «Документы» создаёт акты приёма-передачи, дефектовки, осмотра и списания, служебные записки о неисправности и перечни оборудования. Это отдельный модуль от приватных файлов-вложений `documents`.

## Рабочий сценарий

1. Выбрать до 100 предметов или перейти из карточки имущества с уже выбранным предметом.
2. Выбрать вид документа, заполнить дату и заголовок, ввести обычный текст. Организация и стороны необязательны.
3. Сохранить черновик. Предпросмотр открывается в карточке документа; PDF доступен сразу.
4. При необходимости изменить текст. Фиксация закрывает дальнейшее редактирование этой редакции. Она не является электронной подписью, согласованием, передачей или списанием оборудования.

**Ожидаются типовые документы пользователя.** Встроенные формы составлены как предварительные собственные шаблоны; в интерфейсе и PDF они явно обозначены «Черновой шаблон». Перед применением официальных реквизитов нужно получить утверждённые формы организации. Копирования нормативно обязательной формы либо утверждения о юридической силе здесь нет.

## Сохранение истории

При создании фиксируются точные строки кода, инвентарного и серийного номеров, названия, производителя и модели, кабинета и здания, а также UUID и версия карточки. Одинаковые инвентарные номера разных предметов допустимы и не объединяются. Порядок предметов соответствует выборке команды.

Изменение и удаление карточки оборудования не меняют документ. Ссылка `generated_document_items.asset_id` обнуляется при физическом удалении карточки; JSON-снимок остаётся. Текст и реквизиты документа, версия шаблона и сам шаблон тоже сохраняются в записи. Поэтому замена встроенных шаблонов в следующей версии не меняет существующие документы.

Пока разрешено редактировать текст и реквизиты черновика. Для другого состава оборудования создаётся новый документ. Это сохраняет однозначность исходного снимка и исключает незаметное обновление реквизитов старых актов.

## Безопасность и интеграция

- Чтение разрешено активным `viewer`, `operator`, `admin`; запись — `operator` и `admin`. Публичных ссылок на документы нет.
- Для API требуются scoped bearer token и `Idempotency-Key` при записи. Обновление/фиксация проверяют `expected_version`; создание проверяет версии каждого выбранного предмета.
- Создание берёт общую блокировку физического графа, затем блокирует предметы в порядке ID; снимок не расходится с параллельным перемещением или удалением.
- Поля присваиваются по разрешённому списку. Нельзя передать собственные UUID, статус, версию, HTML-шаблон или системные реквизиты.
- Текст и снимки экранируются фиксированными Blade-представлениями. Пользовательские HTML, PHP и JavaScript не выполняются. Dompdf использует локальные шрифты, изолированный временный каталог и отключённые сеть/PHP/JavaScript.
- PDF генерируется при запросе из сохранённой записи. Временные файлы удаляются, ответ имеет `private, no-store`; постоянный публичный файл не создаётся.

## Контракт маршрутов

Веб-префикс `/document-records`, имена `document-records.*`. API-префикс `/api/v1/document-records`, имена `api.document-records.*`.

| Метод и путь | Действие |
| --- | --- |
| GET `/document-records` | Список; фильтры `q`, `status=draft|final`, `template_key` |
| GET `/document-records/create` | Веб-форма; необязательные `asset_ids[]=UUID`, `q` |
| POST `/document-records` | Создание черновика |
| GET `/document-records/{record:uuid}` | Карточка с сохранённым перечнем |
| PATCH `/document-records/{record:uuid}` | Изменение текста и реквизитов черновика |
| POST `/document-records/{record:uuid}/finalize` | Фиксация редакции |
| GET `/document-records/{record:uuid}/pdf` | Приватный PDF |

Создание: `template_key`, `title`, `document_date` (`YYYY-MM-DD`), `body`, необязательные `organization`, `author_name`, `recipient_name`, массив `asset_ids` (1–100 UUID), объект `expected_assets` (`UUID: version`). Ключи шаблонов: `transfer`, `defect`, `inspection`, `writeoff`, `memo`, `equipment_list`.

Обновление: `title`, `document_date`, `body`, необязательные `organization`, `author_name`, `recipient_name`, `expected_version`. Фиксация: `expected_version`. API создания возвращает HTTP 201; прочие JSON-ответы — 200. Конфликт версий/зафиксированной записи — 409, ошибки полей — 422.

Ссылка из карточки: `route('document-records.create', ['asset_ids' => [$asset->uuid]])`.

Будущие утверждённые формы подключаются новыми версиями структурированных шаблонов в `GeneratedDocumentService::templates()` и фиксированных представлениях. Загрузка произвольного исполняемого Blade/PHP/HTML-шаблона из интерфейса не предусмотрена.
