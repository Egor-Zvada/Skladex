# Списание оборудования

В карточке имущества оператор указывает причину списания. Предмет исчезает из основного реестра и гостевых списков и появляется в разделе **Списание**. Его состояние, код, кабинет, причина, автор и время сохраняются. Активные планы обслуживания автоматически приостанавливаются; их прежние настройки остаются в снимке. Дата выполненного обслуживания при этом не создаётся.

Перед списанием необходимо отсоединить физическое размещение и комплектующие, исключить предмет из комплекта, освободить лицензии, перенести установки ПО, завершить инвентаризацию и разобрать открытые работы и заявки. Эти проверки действуют также для прежней команды изменения статуса через `/assets/{uuid}/move`.

Оператор может вернуть предмет из списания, явно указав причину, кабинет и статус. Плановые работы и лицензии автоматически не включаются.

Автоматического удаления нет. Администратор может полностью удалить выбранный списанный предмет, введя его точный код и причину. Для API нужны `read`, `write`, `purge-assets` и `Idempotency-Key`. Перед удалением создаётся зашифрованная резервная копия в закрытом хранилище `deletion-backups/`. Сбой записи копии отменяет удаление.

Карточка имущества физически удаляется из БД. Сохраняются аудит, исходные даты и авторы перемещений, снимки подготовленных документов и резервирование прежнего кода, UUID и QR. Старый QR после удаления возвращает отсутствие карточки и никогда не назначается другому предмету.

Приостановленные планы, по которым ещё не создавались сроки обслуживания, удаляются вместе с предметом после сохранения снимка. Закрытые работы, инвентаризации, история лицензирования, состава ПК и загруженные вложения блокируют удаление, чтобы не разрушить связанные факты. Причины блокировки показаны в карточке списания. Такое оборудование может оставаться в списании без срока хранения.
